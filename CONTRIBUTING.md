# Contributing

Thank you for considering a contribution. Focused bug fixes, tests, documentation improvements, and changes that strengthen a project's stated purpose are welcome.

## Before writing code

- Read the project's README, development notes, and open Issues.
- Use a Discussion for an early idea or design question.
- Open an Issue before undertaking a substantial feature or architectural change so effort is not wasted on work outside the project's scope.
- Never include credentials, private data, licensed sample material, or code you do not have permission to contribute.

## Pull requests

1. Fork the repository and create a focused branch.
2. Follow the project's setup and style instructions.
3. Add or update tests for behavior changes.
4. Run the documented checks locally.
5. Update user-facing documentation and the changelog when appropriate.
6. Complete the pull-request template honestly and keep the change limited to one coherent purpose.

Automated checks are evidence, not a substitute for review. A maintainer will evaluate correctness, security, scope, dependencies, licensing, documentation, and long-term maintenance before deciding whether to merge a contribution. Submission does not guarantee acceptance.

## Commit messages

Use concise, natural, imperative messages that describe the actual change, such as `Handle empty archives without crashing`. Do not manufacture history or split a change into artificial commits.
